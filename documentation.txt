Security Drift Intelligence - Detailed Documentation

====================================================================================================
1. Executive Summary
====================================================================================================

Security Drift Intelligence is a SOC-optimized platform for identifying cloud control drift, prioritizing risk, and enabling analyst response.

The solution combines:
- deterministic security rule analysis,
- supervised machine learning risk scoring,
- behavioral anomaly detection,
- adversary-style attack simulation,
- SOC-centric dashboard and incident submission workflows.

This document covers architecture, core algorithms, delivery artifacts, and user-facing dashboard design.

====================================================================================================
2. Platform Architecture
====================================================================================================

2.1 High-Level Architecture

The platform is organized into four layers:

  1. Ingestion
     - AWS CloudTrail JSON
     - Azure audit JSON
     - CSV drift event exports

  2. Normalization
     - Event fields are unified into a consistent contract
     - Derived features are created from timestamps, status, and contextual text

  3. Analysis
     - Deterministic security rules
     - Random Forest ML risk model
     - Isolation Forest behavioral anomaly model
     - Composite threat prioritization

  4. Presentation
     - Streamlit SOC dashboard
     - Executive and compliance report generation
     - Incident submission record keeping

3. Core Data Processing
====================================================================================================

3.1 Event Normalization

Events are normalized to a shared schema so AWS, Azure, and CSV records can be processed the same way.

Key normalization steps:
- default missing fields such as severity, status, and change_type
- convert timestamps into hour, day_of_week, month, weekend, and after-hours flags
- map `compliance_impact` to normalized codes like NIST, CIS, GDPR, PCI
- derive `severity_score`, `status_score`, and `change_score`
- detect whether the event is approved, CI/CD related, or emergency-related

3.2 Derived Feature Set

The platform uses rich derived features for both ML and anomaly detection:
- severity_score
- status_score
- change_score
- hour
- day_of_week
- month
- is_weekend
- is_after_hours
- has_compliance_impact
- value_changed
- is_approved_change
- is_ci_cd_change
- is_emergency_change

3.3 Context Extraction

Text fields are combined and normalized to identify patterns in:
- change_reason
- control_name
- control_type
- baseline_value / current_value

Regex-driven patterns detect:
- approved change activity
- DevOps/CI-CD deployments
- emergency or break-glass events

====================================================================================================
4. Analysis Engines and Algorithms
====================================================================================================

4.1 Security Rule Engine

The deterministic rule engine maps event evidence to security controls.
Each rule evaluates both text and categorical fields and returns:
- security_rule_score
- rule_risk_level
- matched_rules
- rule_explanations
- compliance_mappings
- recommended_remediations
- recommended_remediation_commands

Key rule categories include:
- CloudTrail and audit logging controls
- Identity and access controls (MFA, admin roles)
- Encryption and data protection
- Firewall and public exposure
- DLP and cloud guardrail policy drift

4.2 ML Risk Engine

A Random Forest classifier is trained on weak labels derived from auditable risk factors.

Model architecture:
- Categorical features encoded with OneHotEncoder
- Numeric features passed through directly
- RandomForestClassifier with balanced subsampling
- Cross-validated via StratifiedKFold

Output:
- ml_risk_score (numeric, probability-weighted)
- predicted_risk_level
- ml_confidence

Training artifacts include:
- trained model file
- schema metadata file
- feature importance list

4.3 Behavioral Anomaly Engine

A separate Isolation Forest detects unusual events using behavior-focused features.
This engine is intentionally independent of direct severity signals.

Features used:
- control_type
- change_type
- compliance_impact
- change_reason
- hour
- day_of_week
- is_weekend
- is_after_hours
- month

Output:
- anomaly_score
- anomaly_flag
- anomaly_confidence

4.4 Threat Prioritization

The final risk score is a weighted ensemble:

    priority_score =
       0.50 * security_rule_score
     + 0.35 * ml_risk_score
     + 0.15 * anomaly_confidence

Additional priority floors ensure critical outcomes remain visible:
- CloudTrail Disabled → mandated critical floor
- MFA Disabled → mandated critical floor
- Encryption Downgrade → mandated critical floor
- Audit Logging Disabled → mandated critical floor
- Public Database Exposure → mandated critical floor

The final priority mapping is:
- 85+ → CRITICAL
- 65–84.99 → HIGH
- 40–64.99 → MEDIUM
- below 40 → LOW

5. Attack Simulation and Analyst Context
====================================================================================================

The attack simulator converts high-priority drift findings into adversary-style scenario narratives.
This is a human-friendly layer that ties technical drift to likely threat behavior.

Example attack patterns:
- Evidence Tampering
- Account Takeover
- Data Exposure
- Visibility Evasion
- Lateral Movement
- Exfiltration Bypass
- Privilege Escalation
- Malware Persistence
- Cloud Configuration Attack

Each scenario includes:
- control_name
- control_type
- priority_level
- priority_score
- anomaly_confidence
- matched_rules
- attack_pattern
- scenario_description
- recommended_remediation
- recommended_remediation_commands

7. Dashboard Design and UX
====================================================================================================

7.1 Design goals
- Present a SOC-friendly command center
- Make high-risk drift immediately visible
- Enable evidence review and analyst decisioning
- Offer incident submission without leaving the dashboard
- Support audit and compliance workflows

7.2 Dashboard structure

Primary tabs:
- Executive Summary
- Security Drift
- Compliance
- LLM Analyst
- Attack Simulation
- Model Assurance

7.3 Analyst workflow

1. Filter alerts by priority, control domain, compliance, and anomaly status.
2. Review top priority events and evidence.
3. Generate security copilot analysis for selected alert.
4. Submit incident information to a CSV-based SOC queue.
5. Review attack simulation patterns for broader adversary context.
